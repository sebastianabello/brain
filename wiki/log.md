- **Contenido**: Traducción y síntesis completa en español sobre el comando `for` en bash. Cubre: (1) Motivación: `for` difiere de `while`/`until` en que provee un medio de procesar secuencias, útil en programación bash. (2) Forma tradicional del shell: sintaxis `for variable [in words]; do commands done`; variable = nombre que se asigna, words = lista opcional, commands = ejecutados en cada iteración. (3) Ejemplos progresivos: (a) lista explícita `for i in A B C D; do echo $i; done` → A B C D, (b) brace expansion `for i in {A..D}` o `for i in {1..5}`, (c) pathname expansion `for i in distros*.txt` con precaución de que si no coincide nada los wildcards se devuelven literalmente; solución: `if [[ -e "$i" ]]; then`, (d) command substitution `for i in $(strings "$i")` para procesar palabras legibles en archivo (ejemplo longest-word que encuentra la cadena más larga). (4) Omitiendo `in words`: si se omite la lista, el for por defecto procesa parámetros posicionales (`$@` implícitamente); versión longest-word2 que usa `for i;` en lugar de `for i in "$@"`. (5) ¿Por qué `i`?: históricamente en Fortran, variables I-M eran automáticamente integers, mientras que otras eran reales (números decimales); esto llevó a usar I, J, K para variables de bucle; de ahí el dicho "GOD is real, unless declared integer". (6) Forma C-style: sintaxis `for (( expression1; expression2; expression3 )); do commands done`; expression1 = inicializa condiciones, expression2 = determina cuándo termina, expression3 = ejecuta al final de cada iteración; equivalente a `(( expression1 )); while (( expression2 )); do commands (( expression3 )) done`; ideal para contadores numéricos. (7) Ejemplo simple_counter: `for (( i=0; i<5; i=i+1 )); do echo $i; done` → outputea 0,1,2,3,4; nota que cualquier expresión aritmética es válida. (8) Aplicación práctica: mejora de `sys_info_page` con función `report_home_space()` reescrita para usar `for` y `printf` (Cap. 21); variables locales format, i, dir_list, total_files, total_dirs, total_size, user_name; condición de superusuario determina dir_list (/home/* vs $HOME); bucle `for i in $dir_list` con comandos find para contar archivos/directorios (-type f/-type d | wc -l), du -sh | cut -f 1 para tamaño; printf "$format" para salida alineada y consistente. (9) Tabla comparativa de construcciones de bucle: `while` para condiciones complejas/bucles indefinidos, `until` opuesto lógico de while, `for (palabras)` para procesar secuencias/listas, `for ((...))` para contadores numéricos/secuencias. (10) Resumen de progresión del script sys_info_page desde Cap. 25 incluyendo parámetros posicionales (Cap. 32), while loops (Cap. 29), for loops (Cap. 33), control de flujo con if/case (Cap. 27/31).

Validación de input: ejemplo `[[ $REPLY =~ ^[0-3]$ ]]` que acepta solo dígito 0-3. (4) Testing: filosofía open source "release early, release often"; bugs más baratos de arreglar cuanto antes se detectan; stubs del Cap. 26 para verificar flujo; hacer código peligroso seguro para pruebas: reemplazar `rm` por `echo rm # TESTING` y agregar `exit # TESTING` al final del fragmento, con comentarios para facilitar identificación y remoción; casos de prueba (*test cases*): elegir input que refleje casos límite (edge) y extremos (corner); para el fragmento de archivo: dir_name existe, dir_name inexistente, dir_name vacío; cobertura de pruebas (*test coverage*); nota de diseño: testing es función del tiempo.
